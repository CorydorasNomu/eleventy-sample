1. 1番目にやること
2. 2番目にやること

### 第2章 HTMLを生成する

#### 2.1 ビルドとプレビュー

初回に依存パッケージをインストールし、HTMLを生成します。

```sh
npm ci
npm run build
```

ブラウザーで確認しながら編集する場合は、次のコマンドを使います。

```sh
npm start
```

- 本文：`src/index.md`
- 共通レイアウト：`src/_includes/manual.njk`
- 見た目と印刷設定：`src/styles.css`

## 第II部 マニュアルを保守する

### 第3章 更新して配布する

#### 3.1 修正内容を確認する

1. Markdownの操作手順を修正します。
2. プレビューで見出し・注意事項・引用を確認します。
3. 印刷プレビューで改ページ位置を確認します。
4. PDFとして保存し、配布します。

<aside class="note" aria-label="注釈">

**注釈：部の切り替えで改ページする**

第II部は印刷時に新しいページから始まります。
画面上では部の間に区切りが表示されます。

</aside>

#### 3.2 配布前のチェック項目

- 文書名と版が正しいこと。
- 警告が色だけでなく「警告」という文字でも識別できること。
- 見出しだけがページ末尾に取り残されていないこと。
- 注釈・警告・コードがページの途中で不自然に分割されていないこと。

表番号は部をまたいで連番にします。

**表3 配布前の確認項目**

| 対象 | 確認内容 |
| --- | --- |
| 図 | 画像とキャプションが同じページに収まること |
| 表 | 表題・見出し・セルの文字が読めること |
| 図表番号 | 手動で記載した図番号と表番号がそれぞれ登場順になっていること |

本文と見た目を分けて管理すると、CSSの変更を文書全体へ反映できます。
